## 1. Team Adoption

### 1.1 Shared Team Configuration

**Problem:** Every team member copies `.mcp-manager.yml` manually. Drift happens.

**Solution:** `extends` field for config inheritance.

```yaml
# .mcp-manager.yml
extends: github:AreteDriver/team-mcp-configs/base.yml@v1.2.0
servers:
  my-local-server:
    command: python3
    args: ["-m", "my_server"]
```

Resolution order (last wins):
1. Base config (from `extends`)
2. Project `.mcp-manager.yml`
3. Env var overrides

**MVP scope:**
- `extends: <url>` supports `https://`, `github:owner/repo/path.yml@ref`, and local `file://`
- `mcp-manager project validate` resolves and validates merged config
- Lockfile pins resolved versions from merged config

**Deferred:** Private repo auth for `github:` scheme (v0.6.0)

### 1.2 Server Groups / Tags

**Problem:** `mcp-manager health` checks all servers. Teams want `mcp-manager health --group backend`.

**Solution:** Add `tags:` list to server entries.

```yaml
servers:
  postgres-mcp:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-postgres"]
    tags: ["backend", "database"]
```

Commands gain `--tag` / `--exclude-tag` filters:
- `mcp-manager health --tag backend`
- `mcp-manager sync --exclude-tag experimental`
- `mcp-manager monitor --tag production`

### 1.3 First-Run Onboarding Wizard

**Problem:** New user installs `arete-mcp`, runs `mcp-manager`, sees help text, leaves.

**Solution:** `mcp-manager init` wizard.

```
$ mcp-manager init
Detected IDE: Cursor
Found existing MCP config: ~/.cursor/mcp.json

What would you like to do?
  [1] Import existing servers into .mcp-manager.yml
  [2] Start fresh with recommended servers
  [3] Skip — I'll configure manually

Recommended for Cursor users:
  • @modelcontextprotocol/server-filesystem
  • mcp-server-git

Add recommended servers? [Y/n]
```

**MVP scope:**
- Detect IDE from installed config files
- Offer to import existing servers
- Suggest 3–5 common servers based on IDE
- Generate `.mcp-manager.yml` and warn if team config is already ignored

### 1.4 Project Template Scaffolding

**Problem:** Teams starting new repos manually create `.mcp-manager.yml`.

**Solution:** `mcp-manager template` subcommand.

```bash
mcp-manager template list          # show built-in templates
mcp-manager template use python    # .mcp-manager.yml + README section
mcp-manager template use node      # .mcp-manager.yml with npx defaults
mcp-manager template use data    # includes postgres, filesystem, git
```

Built-in templates:
- `python` — local Python servers, `mypy` + `ruff` CI gate
- `node` — npx-based servers, `npm audit` CI gate
- `data` — database + filesystem + git servers
- `ai` — common AI tool servers (web search, code analysis)

## 3. Quality Gates

### 3.1 Coverage Target: 90%

**Current:** 88% (2,110 statements, 254 missing)

**Gaps to close:**
- `health.py` — 69% (deep stdio paths, error branches)
- `writeback.py` — 82% (backup/restore edge cases)
- `monitor.py` — 80% (restart loop error paths)
- `exporters.py` — 85% (import error branches)
- `commands/marketplace.py` — 78% (install dry-run, interactive prompts)

**Plan:** +40 tests focused on error branches and deep stdio paths.

### 3.2 Performance Baseline

**Problem:** No benchmarks. Regression risk as features grow.

**Solution:** `pytest-benchmark` suite.

```bash
pytest tests/bench/ --benchmark-only
```

Benchmarks:
- `bench_health.py` — 10 servers, shallow check, target < 500ms
- `bench_sync.py` — write-back to 4 IDEs, target < 200ms
- `bench_discovery.py` — scan 100-server registry, target < 50ms

### 3.3 Stress Tests

- `test_monitor_restart_storm.py` — 50 rapid crashes, verify backoff caps
- `test_health_100_servers.py` — verify no fd leaks
